# 虚拟卷在线换条带模拟（Flask + SQLite）

模拟一块由两块物理盘（每盘 16 槽、每槽 4 KiB）组成的 32 块虚拟卷，在**不停止读写**的
前提下把条带从“单块交替”改成“每 2 块 / 每 4 块换盘”。每个 4 KiB 块按 512 字节扇区
**稀疏存放**：全零扇区不占正文，两块盘的实占空间按真正写入的扇区计。值班员在网页上为
每块盘设置扇区上限，临时槽单独计容（最多暂存一块）。搬运逐批提交，支持在写槽后、提交前
让进程退出，重启后从最后一个已提交位置继续。上限不足或改写导致超额时拒绝本次操作。

## 模型与规则

| 项目 | 实现 |
| --- | --- |
| 物理盘 | 表 `slots`（32 个盘位）+ `slot_sectors`（每块最多 8 个 512 B 扇区），共 32 个 4 KiB 逻辑块 |
| 稀疏正文 | 全零扇区不落库，读取时按缺失补零；实占 = 非零扇区数，初始每块 1 个扇区 |
| 初始条带 | 单块交替：LBN `l` 落在盘 `l%2`、槽 `l//2` |
| 新条带 | 选 `k=2` 或 `k=4`：LBN `l` 落在盘 `(l//k)%2`、槽 `(l//(2k))*k + l%k` |
| 临时槽 | 表 `staging_block`（单行，结构上最多 1 块）+ `staging_sectors`，容量单算，最多 8 扇区 |
| 扇区上限 | 表 `disks` 每盘一个 `sector_limit`，默认 128（16 槽 × 8 扇区）；网页可改 |
| 容量拒绝 | 上限低于当前用量时拒绝设置；改写后实占超过该盘上限时拒绝该次改写 |
| 每批额度 | 表单填写“本批最多写几次盘槽正文”，**临时槽 stage/unstage 也计次**；额度 1 也执行一次搬运，必然推进 |
| 在线读写 | 任意阶段按 LBN 读写；块在临时槽时读/写都落到 `staging`，始终拿到最近一次已提交正文 |
| 值班员改写 | 独立事务立即提交，不占用搬运批次额度；正文随块一起搬到目标槽，补零扇区不再占空间 |
| 崩溃恢复 | 每批是一个 SQLite 事务（rollback journal + `synchronous=FULL`）；提交前 `os._exit(77)`，重启后正文、盘位和（按扇区推导的）用量一并回滚，已提交批次保留 |

### 搬运算法：位置置换的环分解 + 单临时槽 + 可行起点

换条带本质是 32 个盘位之间的一个置换。规划器**按当前盘位**（不假设永远是初始布局，
因此可连续再次换条带）把置换分解成若干“环”，按环顺序逐个搬运。每个环可**从任一位置
进入**，起点不同则搬运顺序不同：

1. `stage`：环起点的块写入临时槽，起点腾出“洞”；
2. 沿环逐条 `move`：把块写进洞，洞继续移动（同盘移动先删源再写目标，不重复计量）；
3. `unstage`：临时槽里的块写进最后留下的洞。

引擎在开始下一环前逐个试算每个暂存起点，选**第一个能让整环全程守住两盘与临时槽上限**
的起点。若下一环没有任何可行起点，或已开始的环下一步会超限，则提交本批已完成的步骤、
标记 `blocked`，并提示哪块盘（或临时槽）还差多少扇区；值班员改写稀疏内容或调高上限
腾出空间后，再执行一批即可从原位置续搬。

### 旧卷升级

旧版“每块一个 BLOB”的 SQLite 卷在打开时自动升级为稀疏扇区表：正文按 512 字节拆成
非零扇区（不丢失任何非零字节），盘位与已记录的搬运进度（含环分解）保留，每盘上限默认
128 扇区。升级在单个事务内完成，失败整体回滚。


## 启动

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据文件放在命名卷 `volume-data`（容器内 `/data/volume.db`），容器重启后
已提交状态保留。

### 本地 Python

```bash
pip install -r requirements.txt
python -m flask --app app.server run --host 0.0.0.0 --port 8000 \
    --without-threads --no-reload --no-debugger
```

数据库路径由环境变量 `VIRTUAL_VOLUME_DB` 覆盖，默认 `data/volume.db`。
注意必须带 `--no-reload`，否则模拟崩溃时 reloader 监控进程会重新拉起服务。

## 网页操作

- **开始换条带**：选择每 2 块或每 4 块换盘，生成搬运计划。
- **执行一批并提交**：填写本批最大写入次数（含临时槽）；勾选“写槽后、提交前退出”
  会让进程以退出码 77 退出，页面自动轮询等待重启后刷新。
- **容量与扇区上限**：显示两盘与临时槽的已用/上限/剩余扇区；为盘 0/1 设置上限，
  上限低于当前用量会被拒绝。
- **在线读 / 改写**：输入 LBN（0..31）；改写正文不足 4 KiB 自动补零、超长截断，
  立即提交；改写后实占会超过该盘上限则拒绝。块在临时槽时同样可读写。
- 页面展示：迁移状态卡（进度、本批写入次数、临时槽占用、容量不足提示、校验结果）、
  两块盘 16 槽位图（含每槽目标 LBN、空洞、暂存标记）、32 个逻辑块的当前盘位/目标盘位
  与扇区占用、各环的起点与进度、最近 25 条事件日志。

## HTTP API（测试/脚本用）

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/snapshot` | 全量状态（块位置、临时槽、迁移进度、事件、校验） |
| `POST /api/migration/start` `{"stripe_k":2\|4}` | 开始换条带 |
| `POST /api/migration/batch` `{"budget":N,"crash":bool}` | 执行一批；`crash=true` 时提交前退出 |
| `GET /api/blocks/<lbn>` | 按 LBN 读（自动识别临时槽），返回 hex 正文 |
| `PUT /api/blocks/<lbn>` `{"body_hex":...}` 或 `{"body":"..."}` | 按 LBN 改写，必须正好 4096 字节 |
| `GET /api/verify` | 校验：32 槽齐全、正文 4 KiB、临时槽 ≤1、各盘/临时槽不超限、稀疏扇区无全零、完成后盘位符合新条带 |
| `GET /api/usage` | 两盘与临时槽的已用/上限/剩余扇区 |
| `POST /api/limits` `{"limit0":N,"limit1":N}` | 设置每盘扇区上限；低于当前用量返回 400 |
| `GET /api/snapshot` 的 `rings` | 每个环的位置、起点偏移、已完成步数 |

## 测试

```bash
python tests/e2e_test.py
```

测试自动起停 Flask 子进程，覆盖：规划器环分解正确性（含从 k=2 布局再次规划 k=4）、
稀疏扇区初始布局与实占统计、上限低于用量/改写超额被拒、非零可行起点选择、
容量不足时部分提交并在腾出空间后续搬、旧卷升级保留正文与搬运进度、额度 1 推进、
临时槽块与盘上块的在线改写、两次“提交前崩溃 + 重启回滚”（正文/盘位/用量一并回退）、
已提交改写在重启后保留、k=2/k=4 搬完后的逐块盘位核对。当前结果：**322 项检查全部通过**。

## 已知限制 / 未做项

- 未在本机实际执行 `docker compose build`（当前环境没有 docker 二进制），仅校验了
  compose 文件结构；镜像基于官方 `python:3.11-slim`，命令与本地验证一致。
- 稀疏存放让“实占”随正文变化；初始与测试正文多为短头 + 零填充，因此初始每块仅占
  1 个扇区（题目允许“全零 512 B 扇区省去正文”）。
- 使用 Flask 内置开发服务器（单线程），未上 gunicorn/uvicorn 等生产 WSGI。
- 正文为模拟数据（初始块头 + 零填充），未模拟真实磁盘延迟、校验和或冗余副本。
